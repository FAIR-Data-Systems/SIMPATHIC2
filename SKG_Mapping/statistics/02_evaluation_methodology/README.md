# 2. Evaluation Methodology

## Data sources (confirmed 2026-09-14)

- **Disease overlap (gold standard)**: the 10 target diseases, evaluated via
  `Utilities/Queries/canonical_disease.tsv` (generated by
  `generate_canonical_lookup.rb` from the MONDO `rdfs:subClassOf+` hierarchy
  in Virtuoso) plus the `canonical_entity{1,2}_uri` vs. `entity{1,2}_uri`
  columns in the merged-evidence `.large` file — see
  [`05_results/README.md`](../05_results/README.md) for the file's
  provenance. This gives an exact-match vs. subclass-match split for
  diseases specifically.
- **Overlap for other entity types** (drug, gene, phenotype): no
  canonicalization hierarchy exists for these, so overlap is exact-URI-match
  only. This limitation must be stated explicitly wherever such a number is
  reported — per-partner ontology granularity (e.g. HPO parent/child
  relations) means an apparent "no overlap" may actually be a hierarchical
  relation, which we cannot currently distinguish for non-disease types.
- **Graph connectivity / entity & relation counts**: `.large` merged-evidence
  file — see [`05_results/README.md`](../05_results/README.md).

## Disease overlap — gold standard (10 core target diseases)

Computed by [`compute_disease_overlap.rb`](compute_disease_overlap.rb) from
`canonical_disease.tsv` (109 rows: 108 specific→canonical mappings for
descendants of the 10 targets, plus the 10 self-mappings) joined against the
merged-evidence `.large` file's `entity{1,2}_uri` (specific,
pre-canonicalization) and `sources` columns. For each of the 10 targets and
each partner: **exact** (the partner used the target's own canonical URI
somewhere), **subclass** (the partner only used a MONDO descendant of the
target), or **none**.

Note: `entity_uri` can itself be a `|`-delimited list of multiple specific
URIs folded into one canonical pair (see `CHANGES.md`) — an earlier version
of this script compared that whole string against the canonical URI without
splitting it first, which understated exact matches for Radboud (5→8) and
Demokritos (8→10). Fixed before reporting; [`disease_overlap.json`](disease_overlap.json)
reflects the corrected computation.

| Partner | Exact match | Subclass-only match | No match |
|---|---|---|---|
| Biovista | 10/10 | 0/10 | 0/10 |
| Demokritos | 10/10 | 0/10 | 0/10 |
| Radboud | 8/10 | 2/10 | 0/10 |

**All three partners cover all 10 gold-standard target diseases** — either
exactly or via a MONDO subclass. Radboud represents 2 of the 10 only through
subtype terms rather than the parent target URI itself:
- Machado-Joseph disease (`MONDO_0007182`) — Radboud uses subtypes
  `MONDO_0017174`/`0017175`/`0017176` ("MJD type 1/2/3") instead of the
  parent term.
- `MONDO_0100184` — Radboud uses subtype `MONDO_0100186`.

This is a clean, verified result because the canonicalization mechanism
(`canonical_disease.tsv`) already exists and was purpose-built for this
question — see `CHANGES.md`. No "insufficiently precise to support a strong
claim" caveat is needed for disease overlap specifically; that caveat still
applies to drug/gene/phenotype overlap, which has no equivalent
canonicalization (see below).

## Overlap for non-disease entity types (drug, gene, phenotype, protein)

Computed by [`compute_entity_overlap.rb`](compute_entity_overlap.rb) from
the split-evidence `.large` file (one-line-per-evidence-source — cleaner
per-partner attribution than the merged-evidence file, where multiple
partners' `rels`/`sources` for the same canonical pair get concatenated
onto one row; see the "IS_ASSOCIATED_WITH" investigation in
[`05_results`](../05_results/README.md) for why that distinction matters).
Exact-URI-match only — **no canonicalization hierarchy exists for these
types**, unlike disease, so this understates true overlap wherever a
partner represents the same real-world entity at different granularity.
Full output: [`entity_overlap.json`](entity_overlap.json).

| Type | Biovista | Radboud | Demokritos | Jaccard B/R | Jaccard B/D | Jaccard R/D |
|---|---|---|---|---|---|---|
| Drug | 431 | 1,277 | 585 | 9.4% | 17.6% | 14.3% |
| Gene | 575 | 722 | 2,128 | 5.5% | 12.0% | 12.0% |
| Phenotype | 631 | 382 | 193 | 8.1% | 10.2% | 8.1% |
| Protein | 575 | 722 | 2,128 | 5.5% | 11.9% | 11.9% |

(Gene and Protein counts are identical per partner — not a computation bug:
in this KG, Gene and Protein nodes co-occur 1:1 via a linking relation on
the same evidence row, e.g. a UniProt `geneid` node paired with its
`uniprot` protein node, so the per-partner presence sets happen to be the
same size even though the URIs are in different namespaces.)

**Overlap is low (5–18% Jaccard) across all three types — well below what
"similarly rigorous leaf-node curation" would predict if it were purely a
matching-method issue.** Investigated whether this is driven by granularity
mismatch or low-quality/"commentary" entities, per your hypothesis:

Sampled 15 partner-exclusive entities per type per partner (`compute_entity_overlap.rb`
counts + [`sample_non_overlap.rb`](sample_non_overlap.rb) for the samples,
random seed 42 for reproducibility). **Finding: the entities that succeeded
in reaching this comparison are, on inspection, legitimate and specific**
— real UniProt gene IDs with real gene names, real PubChem compound IDs
with specific chemical names, real HPO terms with valid `HP_` IDs. No
"commentary" or clearly-wrong entities turned up in these samples. So for
entities that *made it into the graph*, low overlap looks like a genuine
finding — **partners' independent source literature/curation covered
different specific genes/drugs/phenotypes for the same diseases** — rather
than a data-quality artifact.

The "commentary"/noise problem you were expecting is real, but it happens
**upstream of this comparison**, at the entity-mapping stage documented in
[`03_validation_strategy`](../03_validation_strategy/README.md#root-cause-demokritos-phenotype-and-drug-high-failure-rates):
Demokritos's 928 failed phenotype lookups were largely non-ontological
extracted phrases ("Rescue", "Worse", "Emotional"), and 916 of its failed
drug lookups were class-level labels ("Adrenal Cortex Hormones") that can't
resolve to a specific PubChem CID. Those never reach the graph at all, so
they don't appear as "unmatched" entities here — they're simply absent,
which is itself a completeness caveat worth stating in the paper rather
than a cause of the low overlap measured above.

**One genuine data-quality finding from the sampling, unrelated to overlap:**
12 distinct **obsolete HPO terms** (e.g. `obsolete Difficulty walking`,
`obsolete Narcolepsy`, `obsolete Toe walking`) are present in the KG across
2,024 evidence rows — 4,096 row-instances from Biovista, 134 from Radboud.
Worth deciding whether to flag/exclude these for the paper, since obsolete
ontology terms being actively used in a "current" KG is a citable curation
quality issue.
